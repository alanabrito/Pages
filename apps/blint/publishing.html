Store-ready notes for releasing blint.

Release pack covering product positioning, review notes, permissions rationale, and the remaining steps to a clean App Store submission.

Submission pack

  • App name: blint
  • Category: Entertainment (also fits Utilities)
  • Bundle ID: alanabas.blind-tv
  • Support URL, privacy URL, license URL: this site under /apps/blint/

Marketing pitch

blint turns YouTube subscriptions into a channel-surfing experience built for VoiceOver: browse channels, hear each video's details before it plays, and skip forward, back, or between channels with swipes or hardware media buttons — no hunting for small on-screen controls.

Fixed this cycle

  • Removed the stray UISupportedExternalAccessoryProtocols / Bluetooth accessory Info.plist keys that caused the MFi-authorization rejection.
  • Added a PrivacyInfo.xcprivacy manifest for UserDefaults usage (required since May 2024).
  • Added the missing audio background mode so lock-screen playback actually keeps running.
  • Fixed a force-unwrap crash in channel search when the session needed re-authentication.
  • Removed the entire Meta Wearables/Meta AI integration — it never provided working functionality (no voice-command API exists in that SDK).

Still open before submitting

  • Rotate the two YouTube API keys and two OAuth client IDs found committed in early git history — treat them as compromised.
  • Restrict the YouTube API key to iOS app + bundle ID, and to the YouTube Data API v3 only.
  • Move the OAuth consent screen to "In production" and complete Google's scope verification for the full youtube scope (subscribe/unsubscribe) — unverified apps are capped at 100 test users.
  • Archive & Validate in Xcode with a real Apple Developer account before resubmitting.
  • Update the App Store Connect App Privacy questionnaire to match current data collection (Google Sign-In + YouTube API only, no accessory data).

Review notes

The app requires a Google account for sign-in and uses the YouTube Data API for all channel/video data. No camera, location, or Bluetooth accessory access is required. VoiceOver is a first-class use case — reviewers testing with VoiceOver on should find every control labeled and hinted.
